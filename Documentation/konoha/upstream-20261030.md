# Android 15 / Linux 6.6.144 integration

The update is isolated on `upstream/android15-6.6-lts-20261030`.
The original `nethunter-ksunext-upstream` branch remains at
`c039012566b3c2415a10a9ee0cc213529f3f6d02` (Linux 6.6.143).

Upstream: `https://android.googlesource.com/kernel/common`, branch
`android15-6.6-lts`, commit
`8454d10d24f3d282d8d07ae89ae6efb5a7d67f87`.
This was also checked against the live remote after integration.

## Recovery and integration

The earlier merge `9c3df4025813` discarded many automatically merged changes.
Its recorded ancestry prevents a normal subsequent merge from recovering
all of them. Reconstruction of that merge identified 881 resolution paths.
Recovery first restored 673 paths matching known uncustomized snapshots,
then reconciled 146 additional paths with local backports or vendor changes.
Compilation exposed several further missing header/source dependencies.

The result retains KernelSU, NetHunter, WALT, vendor regulator profiles,
Qualcomm additions, and the custom module-loader behavior. Integration work
includes Bluetooth pending-command declarations, Android trace-hook
dependencies, SLIMbus initialization/cleanup ordering, and QRTR flow storage
and socket lifetime changes. The upstream wrapfd removal is included.
The coverage audit also restored missing Android hook call sites in memory
management, RCU, and IPv4/IPv6, plus the upstream mmap-lock hook,
`mem_cgroup_iter`, and `tcp_send_active_reset` exports.

The released kernel already has a different layout from stock Android GKI
in a few structures. Preserve that existing layout rather than silently
changing offsets used by its modules:

- Keep `task_struct.user_dumpable` at its released position.
- Keep the existing per-task stack randomization implementation and layout.
- Retain the former IPv6 GC list slots while the updated GC walks the
  routing tree. Do not insert new padding into the released IPv6 structures.
- Preserve the existing IGMP `mr_maxdelay` layout and its `READ_ONCE` /
  `WRITE_ONCE` race annotations.
- Preserve the already-shipped MMC claim/retune race fix, AF_XDP single-list
  implementation, BPF precision tracking, sockmap FIONREAD accounting, and
  serial-device shutdown callback. Android reverted these changes to avoid
  changing stock GKI's ABI; applying those reverts here would instead change
  Konoha's existing ABI.
- Retain the MMC single-block write retry and conntrack expectation
  namespace/helper fixes already present in Konoha, including safe access
  to the master conntrack under the expectation lock.
- Keep the existing KVM layout and HID report API, with upstream's new HID
  validation in the shared helper. Keep full type declarations visible to
  symbol versioning where they were already visible in the released source.

These are actual layout adaptations. No symbol CRCs were substituted and
no new module-version bypass was introduced.

## Validation

The final arm64 `Image` and all 114 configured modules built successfully.
Final build log: `updated-build-10.log`; matching-configuration baseline log:
`abi-baseline-build-2.log`. Optional driver check log: `optional-build-2.log`.

Artifacts are outside the source checkout at:
`/home/loukious/Android/konoha-upstream-validation-20261030`.

The arm64 configuration was generated from `konoha_defconfig`, with
`KSU_SUSFS` disabled and `nethunter_patch.sh <output> ksu-next` applied,
followed by `olddefconfig`. KernelSU-Next was held at
`7b5fdb7a51600e96fcb4d148f86c4633ddceee63`.
A validation copy of its repository avoids modifying the ignored original
checkout during Kbuild's automatic history fetch.

Compiler: Android Clang 20, `clang-r547379`. ThinLTO, CFI, module versioning,
and warnings-as-errors are enabled. The release script's blanket `-w`
suppression was not used. Existing warning failures in the customized
module loader and LZ4 macros were repaired directly.

Build command, with validation-local `cpio` on `PATH`:

```sh
make -j16 O=/home/loukious/Android/konoha-upstream-validation-20261030/updated-out \
  ARCH=arm64 \
  LLVM=/home/loukious/Android/custom-rom/prebuilts/clang/host/linux-x86/clang-r547379/bin/ \
  Image modules
```

The original 6.6.143 source was also built in a detached temporary worktree
with the same compiler and stock configuration. That baseline required
compilation repairs for a missing IOAM declaration, unused helpers, LZ4
macro guards, and arm64 module-patching declarations.
The NetHunter baseline also needed the already-updated Bluetooth firmware
filename stub marked `inline` in its temporary source checkout.
An additional baseline build uses the updated NetHunter configuration with
KernelSU disabled. Its remaining configuration differences are the removed
wrapfd option and new build-time mcount sorting support. This allows source
changes to be distinguished from NetHunter configuration changes.

Optional compilation checks enable `COMPILE_TEST`, `SLIMBUS`,
`SLIM_QCOM_NGD_CTRL`, and `QRTR` in a separate output directory and compile
`drivers/slimbus/qcom-ngd-ctrl.o`, `net/qrtr/af_qrtr.o`, and `net/qrtr/ns.o`.
These checks passed; they do not test the hardware or load those modules.

## Compatibility evidence

| Reference | Common exports | Changed CRCs | Removed exports | Added exports |
| --- | ---: | ---: | ---: | ---: |
| Rebuilt 6.6.143 with matching NetHunter settings | 18,031 | 7 | 2 | 225 |
| Published `nethunter-6.6.143-26` | 18,019 | 221 | 2 | 237 |

The updated build exports 18,256 symbols. Of the symbols exported by the
matching baseline and listed in the Qualcomm/Xiaomi symbol files, **none
were removed or changed CRC**: 2,522 Qualcomm and 541 Xiaomi symbols checked.
The updated build supplies all 2,526 Qualcomm and all 618 Xiaomi symbols
listed in the updated symbol files.

The seven changed CRCs outside those vendor lists are:
`backing_file_open`, `nf_ipv6_ops`, `nf_queue_entry_free`,
`nf_queue_entry_get_refs`, `nf_register_queue_handler`, `nf_reinject`, and
`ring_buffer_read_start`. They reflect upstream API or queue-lifetime
changes. The removed exports are `ring_buffer_read_prepare` and
`ring_buffer_read_prepare_sync`. Modules using these interfaces need to be
rebuilt or adapted.

Of the 221 CRC differences against the published release, 214 also occur
when rebuilding the original source with the validation configuration and
compiler. Those include 22 core CMA/interconnect/io_uring exports and 192
wireless-module exports. They predate this update and must not be mistaken
for proof of compatibility with the published binary or installed modules.

Detailed comparisons are saved in `abi-comparison.json`, generated by
`compare-abi.py`. `preexisting-release-crc-differences.txt` records the
baseline/release differences.

DWARF layout dumps produced by `pahole` match the rebuilt baseline exactly
for `task_struct`, `mmc_host`, `sk_psock`, `xdp_buff_xsk`, `fib6_info`,
`in_device`, `nf_conntrack_expect`, and `mmc_queue_req`. The dumps and
comparison are saved in `layouts/`.

The published comparison source is the SHA256-verified `Module.symvers`
asset from release `nethunter-6.6.143-26`. Its embedded configuration was
extracted from the release kernel. The validation configuration differs in
compiler, HZ, debugging options, command line, and other settings; the full
configurations are saved with the artifacts.

The imported `android/abi_gki_aarch64.stg` is the upstream GKI reference,
not a claim that this customized kernel has the stock GKI layout.
Symbol-version comparisons do not establish full binary or runtime
compatibility. No device boot, flash, or vendor-module loading test was
performed.
