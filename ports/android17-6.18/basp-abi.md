The append helper calls memcpy with the exact supplied length at 0xddec and advances the cursor at 0xddf8. Curves: `addDataToSpecBuf` at 0xe13c appends wire type then FFC at 0xe204–0xe220; `temp.idx`, `temp.min`, `temp.max` at 0xe224–0xe2d4; step count at 0xe424–0xe444. Transport: `sendDataWithIoctl` at 0x9570 opens the path O_RDWR, allocates its supplied capacity, calls `ParseSpecData` and then issues exact command 0xd0001001 at 0x95f0–0x9600. The encoded size is 4096; the legacy kernel copies PAGE_SIZE and commits on close. `sendDataWithMmap` at 0xad98 maps its supplied length with PROT_READ|PROT_WRITE, MAP_SHARED, offset zero at 0xadf0–0xae08, populates through ParseSpecData, unmaps at 0xae38–0xae40 and closes at 0xae44–0xae48. A single-page mapping matches the kernel-side transport bound. Caller-selected capacity has not been observed by executing the producer.

New overlay implementation choices: parse explicit little-endian byte offsets into const host records, enforce full length/checksum/count/step bounds before callbacks, and reject duplicate indices per group and malformed curve order. Per-file mapping uses a dedicated zeroed page with VMAs and module refs. Driver removal detaches a refcounted transport object before freeing callback state. mmap commits at final release from a private snapshot; ioctl commits synchronously so malformed data or unavailable providers are reported in its return value, and release does not double-commit. This ioctl timing is a deliberate safe implementation choice, not a claim about stock execution. Required nonempty groups use prepare/commit/abort callbacks held under provider SRCU. No provider absence is reported as success.
